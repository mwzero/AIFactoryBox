Request paths

LiteLLM is the API gateway

Native model APIs

LiteLLM routes chat, embeddings and reranking. Open WebUI calls it internally. The configured Presidio pre-call guardrail masks supported chat text before the model call.

Specialized pass-through

LiteLLM forwards explicit OCR, document, audio and standalone anonymization paths to FastAPI. Nginx has no direct FastAPI upstream, and FastAPI publishes no host port.

Community authentication

Nginx validates specialized bearer keys through LiteLLM before forwarding. This does not add fine-grained permissions, token budgets or automatic PII masking to uploaded files.

Current interface

Use one public API address

API Execution path Contract
/v1/chat/completions LiteLLM → provider OpenAI-compatible messages; chat-small
/v1/embeddings LiteLLM → TEI embedding-small + input
/rerank, /v1/rerank LiteLLM → TEI rerank-small, query and documents
/v1/vision/ocr LiteLLM → FastAPI → Tesseract Image upload; Italian/English text; max 20 MiB
/v1/privacy/anonymize LiteLLM → FastAPI → Presidio Standalone text anonymization
/v1/document/to-markdown LiteLLM → FastAPI → Docling Retained adapter; backend compatibility unverified
/v1/audio/transcribe LiteLLM → FastAPI → Speaches Audio upload; Whisper tiny by default
/v1/audio/synthesize LiteLLM → FastAPI → Piper Retained adapter; backend/voice contract unverified

API operations require a bearer key at the public ingress. Model documentation is at /docs; the authenticated specialized schema is at /specialized/openapi.json. The old /v1/embeddings/generate and /v1/security/guardrail routes are removed.

Small defaults, explicit tradeoffs

The runtime and model are separate choices

Current defaults include cloud GPT-4o mini, local BGE small embeddings, MiniLM reranking, Whisper tiny on CPU, and Tesseract OCR. Presidio loads small Italian and English spaCy models.

The embedding and reranking models are English-oriented. These defaults remain under review; no Italian retrieval benchmark or complete model-quality evaluation is claimed.

A container packages an inference runtime; that runtime loads model weights. Docker does not remove RAM, disk or GPU requirements.

The separate minimal variant provides LiteLLM in Python or Docker with Ollama and Gemma 3 1B; real-model validation remains pending. Hardware profiles, a model catalog and a download console remain proposed work. See the minimal guide.

Existing full Compose stack

Configure before starting

git clone https://github.com/mwzero/AIFactoryBox.git
cd AIFactoryBox
cp .env.example .env
# Set random admin/database credentials in .env.
# Add OPENAI_API_KEY only if using cloud chat.
docker compose up -d --build
curl --fail http://localhost/health

Then generate a LiteLLM virtual key and replace the Open WebUI bootstrap placeholder. Follow the complete quickstart for key creation, proxy trust and functional checks.

/health proves only LiteLLM liveness. It does not verify Presidio, model inference or specialized engines. Only Nginx port 80 is published; add HTTPS termination before transmitting bearer keys over an untrusted network.

Scope of protection

PII masking is a specific control

Supported chat text is analyzed and masked before forwarding to the model. Detection can miss entities; images, attachments, tools and arbitrary specialized payloads are not automatically covered. No automatic restoration of original PII is enabled.

Presidio is not a content moderation or prompt-injection service. Full-stack masking with real Presidio and a controlled provider remains to be verified. Read the security boundaries and validation status before confidential use.
